# 🛡️ Blockchain Enterprise (企业级资产审计平台)

**Blockchain Enterprise** 是从个人版 (v0.4) 演进出的工业级资产审计与管理平台。它将区块链的不可篡改性与企业级的权限管理、物理级安全规范深度结合，提供一套高可信的资产全生命周期追踪方案。

---

## 🚀 核心企业级特性

### 1. 🔐 多角色访问控制 (RBAC) 与双因素认证 (2FA)
系统内置了完善的角色权限体系，通过 Session 级中间件强制校验用户身份：
*   **SUPER_ADMIN (超级管理员)**：拥有全权，负责**用户账号增删改查**及系统核心配置。
*   **MANAGER (资产管理员)**：负责实物资产录入、状态更新。**必须持有物理私钥才能执行操作**。
*   **AUDITOR (审计员)**：拥有全局只读权限，负责生成并签署正式审计报告、执行全链校验。
*   **VIEWER (普通员工)**：仅能查看资产列表及空间位置，无法访问敏感哈希或审计后台。

**强制安全加固**：对于 `SUPER_ADMIN` 和 `MANAGER` 等高危操作角色，系统强制要求绑定 **TOTP 双因素认证 (2FA)**（支持 Google Authenticator 等），有效抵御密码泄露风险。

### 2. 🔌 纯 Web3 式端侧签名架构 (Pure Client-Side Signing)
本项目实现了极致的物理安全隔离，告别传统的“机房插 U 盘”模式，引入 Web3 硬件钱包式的交互体验：
*   **绝对无私钥后端**：服务器端**彻底移除了私钥配置**，降级为绝对安全的“纯公钥验签”模式。从物理和代码层面上杜绝了服务器被黑导致私钥泄露的可能性。
*   **两阶段提交机制**：资产上链与状态流转被严格拆分为 `准备数据指纹` 和 `确认授权上链` 两个阶段。
*   **浏览器内存瞬间签名**：管理员只需在自己的办公电脑上插入存放 `private.key` 的 U 盘，**网页将直接在本地浏览器内存中读取私钥，并瞬间完成 Ed25519 密码学签名**。私钥文件绝对不会上传至服务器网络。

### 3. 📜 自动化合规审计与报告
*   **合规评分系统**：一键执行全链扫描，根据哈希链连续性、签名有效性输出 0-100 的直观评分。
*   **正式报告导出**：生成带有唯一 **Report ID**、时间戳及密码学验签明细的 HTML 报告（可一键打印为 PDF）。

### 4. ⚡ 生产级并发与性能优化
*   **Gunicorn 集成**：采用工业级 WSGI 服务器，替代开发版测试服务器，支持更高的内网访问并发。
*   **SQLite WAL 模式**：底层强制开启 **Write-Ahead Logging (WAL)**，解决了多进程环境下的数据库锁定问题，大幅提升读写效率。
*   **结构化审计日志**：记录所有关键操作至 `storage/audit.log`，实现全员行为可追溯。

### 5. 🔄 业务赋能：精细化资产流转状态 (Business Workflow)
*   **全生命周期管理**：摒弃传统区块链系统中简单的“有效/消耗”二元状态，引入了企业级资管系统必备的细粒度状态机。
*   **可溯源的流转记录**：通过扩展底层的幽灵区块设计，支持在不破坏区块链不可篡改特性的前提下，实现“可用”、“领用 (IN_USE)”、“维修 (MAINTENANCE)”、“调拨 (TRANSFERRED)”和“报废 (SCRAPPED)”的无缝流转，并支持附加操作元数据（如领用人、调拨地点）。

## 📂 项目结构与文件作用

为了方便维护和扩展，项目采用了分层架构设计。以下是各核心文件的功能说明：

### 📁 `core/` (核心引擎层)
这是系统的“心脏”，处理所有底层逻辑：
*   **`blockchain.py`**: 核心账本引擎。负责 Merkle Tree 递归计算、哈希链维护、文件分片存储以及所有数据库读写操作。
*   **`crypto.py`**: 纯净验证中枢。只加载并管理 Ed25519 公钥，用于验证所有新区块签名的合法性。
*   **`auth.py`**: 身份验证引擎。负责处理用户登录、密码哈希存储、角色权限检查 (RBAC) 以及用户账号的管理。
*   **`auditor.py`**: 自动化审计员。负责全账本的完整性扫描。它会逐一核对区块哈希、链条连续性和数字签名，最终输出合规评分及审计报告。

### 📁 `api/` (接口路由层)
负责处理前端请求与后端引擎的交互：
*   **`main.py`**: 系统入口。负责初始化 Flask 容器、加载 YAML 配置、挂载中间件并启动 Web 服务。
*   **`routes.py`**: 业务路由定义。包含了所有的 Web 页面渲染逻辑（如首页、登录页、用户管理页）以及 RESTful 数据接口。
*   **`middleware.py`**: 安全中间件。这是系统的“防火墙”，在每个请求到达前强制检查 Session 登录状态、用户权限角色，并生成结构化的审计日志。

### 📁 `config/` (配置层)
*   **`settings.yaml`**: 全局配置文件。集中管理数据库路径、物理 U 盘路径、服务器端口、允许的资产类目等。修改此文件即可改变系统运行环境。

### 🛠️ 运维与部署脚本 (根目录)
*   **`generate_key.py`**: 创世脚本。用于首次安装时生成 12 个助记词并派生出公私钥文件。
*   **`recover_key.py`**: 灾难恢复脚本。当物理 U 盘丢失或损坏时，凭 12 个助记词瞬间找回私钥。
*   **`init_db.py`**: 数据库初始化脚本。用于创建空的资产表和用户表结构。

## 🛠️ 安装与运行

### 1. 环境准备
```bash
# 进入项目目录
cd blockchain-enterprise
# 创建虚拟环境
python3 -m venv venv
source venv/bin/activate
# 安装依赖
pip install -r requirements.txt
```

### 2. 初始化与配置
1.  **生成凭证**：运行 `python generate_key.py` 在 `keys/` 下生成公私钥对（请妥善保管您的 `private.key`，建议存入物理 U 盘）。
2.  **管理员账号**：系统预置 `admin / admin123`。首次登录强制要求绑定 TOTP (Google Authenticator)。
3.  **用户管理**：登录后可进入 **“用户管理”** 页面直接创建普通员工或审计员账号。

### 3. 启动服务 (生产模式)
```bash
export PYTHONPATH=$PYTHONPATH:.
# --timeout 120: 允许一个操作最长跑 2 分钟 (解决 500 错误)
# --threads 4: 允许同时处理 4 个并发请求 (解决局域网其他设备访问卡顿)
venv/bin/gunicorn --workers 1 --threads 4 --timeout 120 --bind 0.0.0.0:8080 api.main:app
```
访问地址：`http://服务器内网IP:8080`
